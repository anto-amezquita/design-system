**Task 1.2 design note — where each field comes from.** Written before starting, because the obvious source is the wrong one.

`docs/components.md` looks like the source for prop tables, but only **8 of 28** components have a `**Props / variants**` section (Button, Card, Input, Dialog, Select, Tag, Hero, Breadcrumb). The other 20 are bare four-row tables. A generator that reads props from `components.md` produces empty prop tables for two thirds of the system — and an agent reading an empty prop table concludes the component takes no props.

So:

| Field | Source |
|---|---|
| name, slug, tier, purpose, storybook path | `tokens/component-registry.json` |
| import path | derived from package name + tier + name |
| **props, with literal unions spelled out** | **parse the `.tsx` type alias** (e.g. `type ButtonProps = {…}`) — not `components.md` |
| tokens | `tokens/components/<name>.json`, resolved values from `token-reference.json` |
| usage example | the `Default` story in `<Name>.stories.tsx` |
| a11y notes | `components.md` where present; omit the section entirely when absent |

Rule for every field: **omit the section rather than emit an empty one.** A missing section says "not documented"; an empty table says "none exist," and only one of those is true.

Separately: the thin `components.md` entries are a real gap worth filling for humans too, but that is a docs backlog item, not a blocker for 1.2. `llms.txt` links to URLs the docs site does not serve until 1.5. **Do not announce, link, or reference `llms.txt` anywhere — README, case study, LinkedIn — until 1.2 and 1.5 have both landed and the links resolve.** An index of dead links is worse than no index: an agent that fetches it once and gets 404s has no reason to try again. This gate is repeated in the header comment of `build-llms-txt.mjs`.

**Internal components:** components can be flagged `| **Internal** | \`yes\` |` in `docs/components.md`. The registry carries the flag through as `internal: true` and adds `meta.publicComponentCount`; the llms generator excludes them from both files. BaseSheet is the only one today — it ships because Drawer imports it, but an agent should never see it as available. Task 1.2 must apply the same exclusion when generating `.md` twins.

**Acceptance:** `curl https://amezquita.dk/llms.txt` returns content; deleting a component and rebuilding removes it from every artifact with no manual edit; CI fails if artifacts are stale.

**Why this order:** it takes the system from 1/5 to 2/5 on the field benchmark, and it's the prerequisite for Phases 3 and 4 — both consume these artifacts rather than duplicating them.
